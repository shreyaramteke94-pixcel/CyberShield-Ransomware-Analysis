EXECUTIVE SUMMARY
-----------------
This simulated quarterly report is used to demonstrate the CyberShield
Decryption & Recovery Engine. When you encrypt this file with the CyberShield
demo utility, it is protected with AES-256-GCM authenticated encryption.

The encryption:
  - Uses a freshly generated 256-bit key each time
  - Includes an integrity-protecting GCM authentication tag
  - Embeds the SHA-256 of this plaintext in the encrypted header
  - Will REJECT any incorrect key or tampered ciphertext

To recover this file, you must supply the EXACT key that was shown
when the file was encrypted. If the key is lost, this demo file cannot
be recovered — which illustrates why ransomware victims face genuine data
loss when encryption keys are not in their possession.

LESSON LEARNED
--------------
Ransomware recovery is only possible when:
  (a) The encryption scheme has a documented cryptographic weakness,
  (b) Law enforcement has recovered the threat actor's keys,
  (c) A clean backup is available, or
  (d) The victim possesses the decryption key.

CyberShield helps you check options (a) and (b). Options (c) and (d)
depend on your organisation's backup and key management practices.
